# US-3.3 — Configure Project Settings

> **Product decision update — US-6.2:** Locked Project Settings are fully
> read-only. Project Name rename remains allowed as the non-scheduling
> Project-field exception owned by US-3.1; it does not make Settings editable.
> Planning changes require explicit Project Reopen (`Locked → Open`). Complete
> Actual Date remains a Task-level factual-data exception. Daily Capacity,
> Member Buffer, Capacity Override, Public Holiday, Project Buffer, and other
> scheduling-impacting settings use the generic cross-project impact
> warning/blocking contract. Project Buffer affects Commitment only and does not
> alter Actual BAU Capacity. Forecast behavior while Locked is deferred.

> **Product decision update — US-7.1:** The shared Add/Edit Project form may be
> opened from Projects or directly from Project Name on Home. Home invocation
> remains over Home without background routing. The standalone Project Structure
> entry point is removed. Project lifecycle actions remain owned by US-3.1.

> **Product decision update — US-6.1:** Automatic Scheduling is the only
> activation configuration for generated Execution/Commitment timelines and
> Auto Dependency by Assignee. Member Buffer affects Execution Capacity; Project
> Buffer is applied afterward for Commitment Capacity.

## 1. User Story

**As an** Engineering Lead
**I want** to configure project scheduling settings
**So that** the Scheduling Engine follows the project-specific planning strategy.

---

## 2. Business Context

Project Settings determine whether a Project is scheduler-driven or manually
planned. They also provide the only Project-level scheduling anchor and the
Project Buffer used by the Commitment Scheduler.

This story owns configuration, persistence, validation, UI behaviour, and
coordination with the Scheduling Engine. Concrete Execution and Commitment
algorithms are owned by US-6.1. Forecast remains independent.

There is no separate `Auto Dependency by Assignee` toggle. Auto Dependency is
active only when `Automatic Scheduling = ON`.

---

### 3.1 In Scope

- Configure Project Buffer (%).

### 3.2 Out of Scope

## 4. Domain Model

| Field                 | Type               | Required | Default | Rules                                                          |
| --------------------- | ------------------ | -------: | ------: | -------------------------------------------------------------- |
| Automatic Scheduling  | Boolean            |       Ya |  `true` | Only activation config for generated dates and Auto Dependency |
| Scheduling Start Date | Nullable date-only |    Tidak |  `null` | SQL `DATE`; API `YYYY-MM-DD`; Project-level anchor             |

## 5. Product Rules

### 5.1 Automatic Scheduling ON

- Execution and Commitment timelines are generated by US-6.1.
- Execution and Commitment dates are read-only.
- Auto Dependency by Assignee is active.
- Assignee, Effort, Lag, manual dependency, WBS ordering, and Project Priority
  changes use the concrete scheduler triggers defined by US-6.1.
- Forecast remains active through its own contract.

### 5.2 Automatic Scheduling OFF

- Execution and Commitment timelines are manually maintained.
- Existing generated values become initial manual values after confirmed Save.
- Auto Dependency is not created, removed, or reconciled by Task mutations.
- Existing dependency graph remains visible.
- Lag remains stored but does not change manual dates.
- Project Buffer is inactive but preserved.
- Forecast remains active.

### 5.3 Scheduling Start Date

- It is the single Project-level anchor for Automatic Scheduling.
- It is optional while Automatic Scheduling is OFF.
- Automatic Scheduling may be ON without an anchor, but generated Execution and
  Commitment dates remain empty.
- UI warning is exactly:

```text
Automatic Scheduling requires a Project Scheduling Start Date.
```

- The scheduler must not invent another Task-level or system-level anchor.
- The first schedulable Task without blockers starts no earlier than this Date,
  after capacity and availability rules are applied.
- Calendar behaviour follows the shared single-date control and is disabled when
  Project Settings are read-only.

### 5.4 Project Buffer

- Default `20`.
- Valid range `0`–`100` inclusive.
- Editable only while Automatic Scheduling is ON and Project Settings are
  editable.
- Disabled but preserved while Automatic Scheduling is OFF.
- Applied after Member Buffer to derive Commitment Capacity.
- Does not affect Execution Capacity.

### 5.5 Capacity Formulas

For each Team Member and Date:

```text
Resolved Daily Capacity
= Public Holiday / Capacity Override / Daily Capacity result

Execution Capacity
= MROUND(
    Resolved Daily Capacity × (1 - Member Buffer Percentage / 100),
    0.5
  )

Commitment Capacity
= MROUND(
    Resolved Daily Capacity
    × (1 - Member Buffer Percentage / 100)
    × (1 - Project Buffer Percentage / 100),
    0.5
  )
```

Example:

```text
Resolved Daily Capacity = 8 hours
Member Buffer = 30%
Project Buffer = 20%

Raw Execution Capacity = 8 × 70% = 5.6 hours/day
Execution Capacity = MROUND(5.6, 0.5) = 5.5 hours/day
Raw Commitment Capacity = 8 × 70% × 80% = 4.48 hours/day
Commitment Capacity = MROUND(4.48, 0.5) = 4.5 hours/day
```

Rules:

- Execution Capacity is rounded to the nearest `0.5` hour after Member Buffer.
- Commitment Capacity applies Member Buffer and Project Buffer to Resolved Daily Capacity, then rounds the final result to the nearest `0.5` hour.
- Deterministic decimal arithmetic is required and allocation is not rounded to whole days.
- Execution and Commitment schedules allocate Effort per day and persist
  inclusive date-only Start/End boundaries.
- Project Buffer does not extend the Execution result mechanically; Commitment
  is independently scheduled using Commitment Capacity and the same effective
  dependency graph.

### 5.6 Project Status

#### Open

Project Settings may be modified subject to validation.

#### Locked

Project Settings are visible and read-only. Project Name remains editable through
the shared form under US-3.1, but it is not a Setting and does not enter this
story's mutation payload/impact workflow. Locked Execution/Commitment baseline
remains immutable. Actual Date entry on an unfinished Task does not make
settings editable; its Actual Allocation may recalculate impacted Open Projects
under US-6.2. Reopen Task is unavailable while Locked; the Project must first
use explicit `Locked → Open` Reopen. Forecast behavior while Locked is deferred.

#### Closed

Project Settings are entirely read-only.

### 5.7 Save Behaviour

- Toggle or field changes remain draft until Save.
- Cancel restores confirmed values and sends no mutation.
- OFF→ON requires confirmation.
- Every scheduling-impacting settings change runs US-6.2 transitive impact simulation.
- Open-only cross-project impact requires grouped Project-name confirmation and server revalidation.
- Any impacted Locked Project blocks the settings change atomically.
- With Scheduling Start Date configured, confirmed OFF→ON runs US-6.1 scheduling for the allowed transitive impacted Open scope as part of one atomic operation.
- If settings persistence, impact validation, or scheduling fails, all changes roll back and confirmed settings/timelines remain unchanged.
- OFF→ON without Scheduling Start Date saves the settings, does not invoke
  scheduling, keeps generated dates empty, and displays the approved warning.

### 5.8 ON → OFF

After confirmed Save:

- Existing generated Execution and Commitment timelines become initial manual
  values.
- Unfinished Tasks become manually editable according to US-4.1.
- Completed Tasks remain read-only.
- Project Buffer becomes inactive but remains stored.
- Automatic dependency ownership is preserved; it is not recalculated while OFF.

### 5.9 OFF → ON

After confirmed Save with a valid anchor:

- US-6.1 recalculates unfinished Tasks only across the transitive impacted Open scope.
- Tasks with complete Actual Date remain completed historical anchors.
- Manual dates of unfinished Tasks are replaced by scheduler-generated dates.
- Stored Project Buffer becomes active.
- Auto Dependency is reconciled from confirmed Assignee, priority, WBS order,
  capacity, and dependency state.

### 5.10 Forecast

Forecast implementation remains outside this story. No Forecast behavior for Locked Projects may be inferred from earlier wording; it is deferred to its owning requirement.

## 6. UI Behaviour

- Project Name and Project Settings use one reusable Add/Edit Project form.
- The form may be composed by Projects or Home; Home opens it directly over Home
  and does not route through Projects or Project Structure.
- Because Project is WBS level `0`, Edit Project also includes the read-only Project Summary owned by US-4.3 after the Project fields; it is not a setting and is not submitted.
- Edit Project uses the existing shared wide Dialog variant. Add Project has no confirmed Task subtree, omits Project Summary, and may retain the standard dialog width.
- There is no separate Settings or Summary action.
- Controls have visible labels and accessible descriptions.
- Project Buffer is disabled while Automatic Scheduling is OFF.
- Scheduling Start Date remains visible while OFF and may be edited.
- OFF→ON confirmation explains that manual dates of unfinished Tasks will be
  replaced and automatic dependency will be recalculated.
- Draft is preserved after validation or operation failure.
- Duplicate Save is prevented.
- Success updates confirmed settings and generated dates without hard refresh.
- Failure preserves the previous confirmed settings and timelines.
- Project Summary loading/error is isolated to its region, supports Retry, preserves form draft, and does not block valid settings Save/Cancel.
- The wide dialog remains responsive and its summary sections stack before form actions when horizontal space is insufficient.

## 7. Acceptance Criteria

1. Automatic Scheduling defaults to Enabled.
2. Automatic Scheduling is the only activation config for generated Execution/Commitment dates and Auto Dependency.
3. No `Auto Dependency by Assignee` field or toggle is exposed or accepted.
4. Project Buffer defaults to `20`.
5. Project Buffer accepts `0`–`100` inclusive.
6. Project Buffer is editable only while Automatic Scheduling is ON and settings are editable.
7. Project Buffer is disabled but preserved while Automatic Scheduling is OFF.
8. Changes apply only after Save; Cancel sends no mutation.
9. ON→OFF retains generated timelines as initial manual values.
10. ON→OFF stops Auto Dependency reconciliation without deleting confirmed dependency ownership.
11. OFF→ON requires confirmation.
12. OFF→ON with a valid anchor invokes US-6.1 atomically.
13. Scheduler failure during OFF→ON rolls back settings and timelines.
14. OFF→ON without an anchor saves settings, does not invoke scheduling, keeps generated dates empty, and shows the approved warning.
15. OFF→ON recalculates only unfinished Tasks; completed Tasks remain fixed.
16. Execution Capacity equals Resolved Daily Capacity after Member Buffer.
17. Commitment Capacity is calculated from Resolved Daily Capacity after Member Buffer and Project Buffer, then rounded independently to `0.5` hours.
18. Example `8`, `30%`, `20%` produces rounded Execution `5.5` and rounded Commitment `4.5` hours/day.
19. Execution Capacity is rounded once to `0.5` hours before Project Buffer is applied.
20. Execution and Commitment dates are read-only while Automatic Scheduling is ON.
21. Manual Execution and Commitment dates are editable only while Automatic Scheduling is OFF and other lifecycle rules allow it.
22. Forecast implementation remains deferred; this story defines no Locked Project Forecast behavior.
23. Locked Projects reject Project Settings updates without changing status; Project Name rename remains allowed through US-3.1 and does not invoke settings impact/scheduling.
24. Closed Projects reject Project Settings updates.
25. Project Name and settings share one Add/Edit form.
26. Scheduling Start Date is visible and editable whenever Project Settings are editable.
27. Automatic Scheduling without Scheduling Start Date never invents Task dates.
28. Mutation state prevents duplicate Save, preserves draft on failure, and refreshes confirmed settings without hard reload.
29. Controls, confirmation, warning, validation, and focus behaviour are keyboard-accessible and usable on supported viewports.
30. Edit Project uses the existing shared wide Dialog variant and composes the US-4.3 whole-Project summary after Project fields and before form actions.
31. Add Project does not display Project Summary and is not required to use the wide variant.
32. Project Summary is read-only, excluded from Project create/update payloads, and does not alter Open/Locked/Closed settings permissions.
33. Project Summary local loading/failure/Retry preserves draft and does not block otherwise valid Save/Cancel.
34. On narrow supported viewports the wide Edit Project dialog remains within viewport padding, summary sections stack in semantic order, and form actions remain reachable without horizontal scrolling.
35. Scheduling-impacting Settings/Project Buffer changes use grouped cross-project impact warning, Locked blocking, server revalidation, and atomic transitive Open recalculation.
36. Project Buffer does not alter Actual BAU Capacity.
37. Activating Project Name on Home opens the same Edit Project form directly over Home and returns to Home after Save/Close.
38. Locked Edit Project permits Name only and rejects any Settings change atomically without partial Name update.

## 8. API Contract

Project create and update accept these settings beside Name:

```json
{
  "name": "Alpha",
  "automaticScheduling": true,
  "schedulingStartDate": "2026-08-03",
  "projectBuffer": 20
}
```

A dedicated settings endpoint may be retained if consistent with repository
convention:

```http
PATCH /api/projects/{projectId}/settings
```

```json
{
  "automaticScheduling": true,
  "schedulingStartDate": "2026-08-03",
  "projectBuffer": 20
}
```

Requests containing `autoDependencyByAssignee` are rejected as unknown or
non-writable input. Status remains absent and changes only through lifecycle
commands.

## 9. Test Cases

### Happy Path

- Create Project using default settings.
- Enable and disable Automatic Scheduling.
- Change Scheduling Start Date and Project Buffer with no external impact.
- Change Project Buffer impacting Open Projects and confirm grouped warning.
- Change Project Buffer impacting a Locked Project and verify atomic rejection.
- ON→OFF preserves generated dates as manual values.
- OFF→ON with anchor runs concrete Execution/Commitment scheduling.
- OFF→ON reconciles Auto Dependency.
- `8`, `30%`, `20%` produces rounded Execution `5.5` and rounded Commitment `4.5`.
- Re-enable and verify only unfinished Tasks are recalculated.

### Validation and Failure

- Project Buffer below `0` or above `100`.
- Invalid Scheduling Start Date format.
- Request includes removed `autoDependencyByAssignee`.
- Locked Settings update, including a request that mixes Name and Settings.
- Closed Project update.
- Cancel with unsaved changes.
- OFF→ON without anchor.
- OFF→ON scheduler failure rolls back settings and dates.
- Duplicate Save sends one mutation.
- Old response cannot restore stale settings after success.
- Project Summary loading failure and Retry do not clear settings draft or block Save.
- Older WBS summary response cannot replace newer confirmed Project Summary.

### Regression

- Forecast implementation remains deferred and no Locked behavior is asserted.
- Tasks with complete Actual Date remain completed historical anchors.
- Stored Project Buffer is reused after re-enabling.
- Project Buffer never changes Execution Capacity.
- Member Buffer affects both Execution and Commitment through the formula chain.
- Automatic dependency is not reconciled while OFF.
- Edit Project wide layout and US-4.3 summary do not change Settings payload or lifecycle permissions.
- Home and Projects compose the same form without duplicate validation/orchestration.
- Locked Name-only rename does not invoke settings impact preview or scheduler.
- Add Project remains summary-free.

## 12. Locked Product Decisions

- Automatic Scheduling default = Enabled.
- Automatic Scheduling is the only activation config.
- There is no separate Auto Dependency config.
- Scheduling Start Date is the only Project scheduling anchor.
- Project Buffer default = `20`; valid range `0`–`100` inclusive.
- Execution Capacity applies Member Buffer.
- Commitment Capacity applies Project Buffer after Member Buffer.
- Execution and Commitment Capacity are each rounded once, independently, after all buffers relevant to that timeline have been applied.
- Automatic Scheduling OFF makes Execution and Commitment manual and pauses Auto Dependency reconciliation.
- Forecast behavior for Locked Projects is deferred.
- Tasks with complete Actual Date remain completed historical anchors during OFF→ON recalculation.
- Locked and Closed Projects cannot modify Project Settings.
- Locked Project may rename Project Name only under US-3.1; Name is not a Setting
  and does not invoke this story's impact/scheduler flow.
- Home and Projects reuse the same Add/Edit Project form; Home never routes
  through Projects or Project Structure.
- Edit Project also composes the read-only US-4.3 whole-Project summary and uses the shared wide Dialog variant; Add Project omits summary.
- Project Summary is excluded from Project mutation payloads and its loading/error state does not block settings Save/Cancel.
- Changes apply only after Save.
- OFF→ON scheduling and settings persistence are atomic when an anchor exists.

## 13. Deferred Implementation

- US-6.1 owns concrete Execution and Commitment scheduling and Auto Dependency.
